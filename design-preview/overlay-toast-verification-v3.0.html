一、自定义在哪

元素Windows 系统通知本卡片
左侧 应用小图标（16–24px） StuMate 品牌标识 46dp —— 课表九宫格 + 待提醒格 + 铃铛，多色不跟随 tint
底色 纯色亚克力灰 accentTint → 透明 的竖向渐变，顶部一层强调色氛围
进度 没有这个概念 上课进度条（4dp，surface3 槽 + accent 填充）—— 一眼看出「这节上到哪了」
时间 绝对时间戳 右上角实时倒计时：「已上课 25 分钟」/「还有 12 分钟」
操作 系统按钮样式 Fluent FlButton「知道了」，与主界面同一套控件

进度与倒计时都从时间区间现算，不是额外状态；区间退化（end <= start）时 降级成「只显示时间」，不做除零。

二、位置与几何

项取值
窗口460 × 176 dp，无边框、置顶、不可缩放
位置工作区（已扣掉任务栏）水平中线，距上沿 24 dp
为什么是 24 不是 16系统通知用 16。顶部横条压得太贴边会「显得像系统级 UI」，24 更像应用自己的东西
圆角 / 描边走 DWM（Win11 原生圆角 + 跟随主题的 1px 描边），与主窗口同一套
任务栏WS_EX_TOOLWINDOW —— 不占任务栏、不进 Alt+Tab
抢焦点不抢。只 toFront() 抬高 z 序 —— 提醒不该把你正在输入的光标夺走
进场从上方落下 200 ms
关闭「知道了」按钮；点过卡片之后 Esc 也能关

⚠️ 顺序坑：toFront() / setAlwaysOnTop 会让 AWT 按它自己缓存的样式 重写 GWL_EXSTYLE，把 WS_EX_TOOLWINDOW 抹掉。 所以工具窗口标记必须排在它们之后下发（代码里用 repeat(6) 兜底重试）。

六、这一版顺手修掉的一个渲染 bug

第一版卡片做出来，肉眼看顶部是一片亮银，不是「深色卡片顶部微亮」。采样确认：

采样点实测预期
卡片顶部 padding 区（深色主题）rgb(230, 243, 249) 亮银rgb(49, 61, 66)

根因：卡片根 Box 只写了渐变、没铺不透明底色。渐变的起始色 accentTint 是 0x1F 半透明（α≈0.12）， 于是它和窗口自身的白底混合 → 白 + 12% 蓝 = 亮银。

修法两处一起：

// 1) 卡片根：先铺不透明底色，再叠渐变
.background(c.surface)                                        // ← 新增
.background(Brush.verticalGradient(0f to c.accentTint, 0.45f to Color.Transparent))

// 2) 窗口自身的底色也跟着主题走，别留白
LaunchedEffect(surface) {
    runCatching { window.background = java.awt.Color(surface.toArgb(), true) }
}

修完实测：卡片顶部 rgb(49, 61, 66)，与「surface #2B2B2B 上叠 12% #60CDFF」的 理论值 (50, 63, 69) 一致。
第 2 处不只是为了这个 bug —— 进场的 alpha 渐隐阶段也会闪白。

七、已知限制（会写进设置页文案）

  • 对独占全屏的游戏 / 播放器可能压不住 —— 与安卓上 ColorOS 拦截全屏弹窗是同一类平台限制。
  • 不做「卡片以外逐像素透明」。试过两条路，都不成立，且无法自证： Window(transparent = true) 根本没建出分层窗口（WS_EX_LAYERED 从未置位）； 手写色键 LWA_COLORKEY API 层回 ok=1 但实机仍全屏不透明。 详见 overlay-transparency-verification-v1.0.html。
  • 本机缩放在两次测量之间从 200% 变成过 100%。卡片位置与缩放无关（用工作区算，不除 density）， 两种缩放下都实测正确。
