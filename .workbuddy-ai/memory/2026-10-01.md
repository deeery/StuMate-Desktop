## 重绘品牌图标并替换（侧栏 / 托盘 / 任务栏）

### 先量了截图，不靠肉眼

截图 36×34，取色与几何：
- 外接框 26×26（= 旧版 `Box(Modifier.size(26.dp))` 的实测像素，本机 1:1 无缩放）

### 设计比选（做了两轮，共 10 个方案）

用 Edge 无头模式（`msedge --headless=new --screenshot`）把候选渲染成 PNG 后逐个看，淘汰过程：

| 方案 | 结果 |
|---|---|

| **S 由 3 条通栏 + 2 个错位连接块拼成** | ❌ **读成「Z」**。连接块占 55% 宽，错位量不够；块状 S 与块状 Z 本来就难分 |
| S + 3×3 网格线（线粗 10） | ❌ 读成「瞄准镜十字」，不像课表 |
| S + 密网格线（6 条） | ❌ 太花 |
| S + 圆点 | ❌ 圆点像一颗球，不像通知徽标 |

### 坑：`Icon()` 默认整体染色（已写进项目 MEMORY 坑 18）

必须传 `tint = Color.Unspecified` 才会跳过 `ColorFilter`。

## v2.1：铃铛圆润化（用户反馈「像圣诞树」，并要求参考开源图标）

用户两条反馈：①「铃铛离心率更小、更圆润、更像铃铛而非圣诞树」②「看看有没有开源的铃铛图标做参考」。

### 先去拉真实开源 path，再动手（这步是关键）

用 curl 从 GitHub raw 拉了 5 个主流图标集的铃铛 SVG，**量它们的真实几何**：

| 图标集 | 许可 | 圆顶直径 ÷ 底沿宽 | 铃身高宽比 |
|---|---|---|---|
| Lucide `bell` | ISC | **75%**（r6 / 宽16） | 0.94 |
| Bootstrap `bell-fill` | MIT | **71%**（r5 / 宽14） | 0.86 |
| Heroicons `bell` | MIT | **76%** | 0.83 |
| Phosphor `bell-fill` | MIT | **100%**（r80 / 宽160） | 1.10 |
| Tabler `bell-filled` | MIT | ≈100% | ≈1.06 |
| **我的 v2.0** | — | **46%** ❌ | 0.90 |

**关键结论**：「像圣诞树」**跟高宽比无关**（v2.0 的 0.90 本来就在正常区间），
根因是**圆顶只占底沿宽的 46%**，侧腰从 108 一路斜张到 192 —— 那就是个锥形。
主流最低也有 71%。

**另一个发现**：这 5 个开源铃铛**全都没有顶钮**，圆顶本身就是顶。
我 v2.0 加的顶钮实测读成「圣诞球」。

### 分两派，选窄腰派

- **窄腰派**（Lucide / Bootstrap / Heroicons，圆顶 71–76%）：肩部微收 + 底沿外翻，铃铛感最强。
- **直筒派**（Phosphor / Tabler，圆顶 ≈100%）：侧腰完全竖直 → **实测读成拱门 / 墓碑**，淘汰。

### v2.1 几何

圆顶半径 **54 → 88**（占底沿 75%）、铃身高宽比 **1.06 → 0.88**、侧腰由斜线改为近竖直
（从 176 收着下到 216，仅下缘外翻）、**删掉顶钮**、底沿 `138,300 236×36`、摆锤 `(256,358) r26`。
对齐 Lucide 的 75% / 0.94。

**已验证的硬约束（已写进项目 MEMORY 与代码 KDoc）**：圆顶 ≥70% 底沿宽，否则退化成锥形。

### 验证

## 课表表格「时间格描边」（本会话）

用户：「给表格界面每一个时间用刚刚的颜色做一个描边，使其区别于背景；浅色模式可以用更白的线段」。
（「刚刚的颜色」= 上一轮把最底层底板改成的那层 `#141414`）

### 结论：直接复用底板 token `c.bg` 同时满足两种模式

`WeekGrid()` 新增 `val timeLine = c.bg`：深色下是 `#141414`（比卡片面 `#2B2B2B` 暗 23 级），
浅色下是 `#F3F3F3`（比纯白卡片面浅 12 级，即「更白的线段」）。
**关键判断**：浅色下卡片面是纯白 `#FFFFFF`，比白更白在物理上不存在，所以「更白」只能理解为
「比 outline 那层中灰更浅的线」——`c.bg` 正好是现有 token 里最浅的一档。

### 三处实现要点

1. **画在 `drawBehind` 里、斑马纹之后**：drawBehind 天然在内容之下，于是跨节的课程卡片会把线盖住，
   不会出现「线从课程卡片中间穿过去」。
2. **吸附到整像素**：`drawLine(y = 小数)` 会被抗锯齿摊到相邻两行各占一半浓度。这条线只比底色深
   20 来级，摊薄一半就基本看不见——实测恰好一半的整点落在半像素上（渲染成 `#272727` + `#1D1D1D`，
   其中 `#272727` 只比底色深 4 级）。改成 `drawRect` + `roundToInt()` 吸附后全部是干净的
   单像素 `#141414` / `#F3F3F3`。
3. **纵轴刻度线一起换色**：它与列内网格线在视觉上是同一条线，两段不同色会像画错了。

### 途中发现并修掉的回归：刻度线穿字 = 删除线

纵轴刻度线原本是 `c.outline`（`#3A3A3A`，只比底色深 11 级），压在时间标签上几乎看不见；
换成 `#141414` 后深了一倍多，而标签是**垂直居中压在刻度线上**的，于是「08:00 / 09:00 / …」
全被划了一道横线，看着像删除线。
**修法**：给标签垫一层 `c.surface` 底 + `padding(start = 8.dp, end = 5.dp)`，线在文字处自然断开，
变成标准的「09:00 ————」样式。

### 验证

`compileKotlin` 0 告警；单测 **145 / 145**；深/浅两套主题实机截图 + 像素扫描
（每列线位一致：首 142、末 784、间隔 53px = 1 小时）；课程块遮挡实测通过。

### 工具修正

`tools/shoot_scenarios.py` 里 `-Dstumate.theme=dark` 原来是**写死**的，导致浅色验收只能绕过脚本

`design-preview/week-grid-lines-verification-v1.0.html` + `design-preview/week-grid-*.png`（10 张）。
**改动未提交。**

## 「两种登录方式登同一账号」——客户端界面 + 服务端补修

### 背景

用 GitHub 注册出来的账号 `password_hash = NULL`，而改密接口必须验原密码 ——
这类账号原先**没有任何途径能设上密码**，只能永远靠第三方登录。
本轮把客户端界面补齐，并顺带修掉两个服务端缺陷。

### 客户端（AccountSection.kt 被另一个会话覆盖过一次，重写过）

新增 `SetPasswordDialog`（设置邮箱密码，400dp）/ `ModifyPasswordDialog`（修改密码，380dp），
设置页「账号」分组插入「邮箱密码」一行，**按钮文案按 `has_password` 切换「设置」/「修改」**。

**踩坑**：`ModifyPasswordDialog` 一开始误接了 `resetPasswordWithCode(code="")` ——
查服务端发现早就有 `POST /auth/password`（验原密码）且客户端 `changePassword` 也在。
`reset-with-code` 要管理员发重置码，是「忘了密码」的补救，不是「我想改密码」的正路。已改回。

### 服务端两个真实缺陷

**① 设备重复计数（截图时撞上登录超时才暴露）**
`login` 路由无条件 INSERT 新设备 → 一台电脑反复登录每点一次多一条记录，
点满 5 次被自己的 `DEVICE_LIMIT` 锁死。实测该账号 5 台设备里 4 条都叫 `WIN-TLLCHC604HH`。

修法：`findOrCreateDevice()`（同 `user_id+name+platform` 复用，`device_id` 不变
⇒ 名下 refresh 令牌不受影响）+ `hasDevice()`，上限判断改成
`count >= LIMIT && !hasDevice(...)` —— **只拦新增，不拦同机重登**。
OAuth callback 同步改，但**首次 OAuth 注册**那处仍用 `createDevice`（用户刚建）。
验证：同机连登 7 次全过、设备数恒为 1（修复前第 6 次就被拒）。

## 课程常驻描边（用户反馈「每一个课程还是没有初始描边」）

### 真因：那是交互态描边，不是常驻描边

`CourseBlock` 里 `borderWidth = when { selected -> 1.5.dp; hovered -> 1.dp; else -> 0.dp }`
—— 默认态 `0.dp`，完全没描边。用户要的「初始描边」一直不存在。

### 取色：不能凭眼睛，必须算亮度差

在 `#333333`（深色卡片面）/ `#E0E0E0`（浅色卡片面）上实测各候选：
`outline` Δ7 / `#E5E5E5` Δ5（太弱）；`outlineStrong` Δ23/Δ24（像选中态）；
`bg` Δ31/Δ19（**第一版用了这个 —— 效果不对**）。

`c.bg` 在深色下 Δ31 虽够清楚，但方向是「比卡片面暗」= **挖槽**，
深色主题里看着每个格子都被挖空了，边框硬得像刻上去的。Fluent 实际做法是**发光**。
最终 `borderRest`：深色 `#404040`（Δ+13）/ 浅色 `#D2D2D2`（Δ+14）。

**教训**：`c.bg` 这类为「页面底板」设计的极端值不能挪去做元素描边 ——
它的语义是对比页面根，不是对比同层卡片。

### 顺序坑：border 必须排在 clip 之前

`border()` 画在组件**内侧**，`clip → background → border` 会让 4dp 圆角
把描边切出缺口（四角断口）。改成 `border → clip → background` 后四角连续。

### 像素实测（比肉眼可靠）

沿课程块左边界垂直扫描 x=300：
`y=143 #333333 → y:144 #404040 → y:145 #333333`
描边精确落值、1px 无抗锯齿摊薄。同一条线上 `y=142 #141414` 是整点分隔线，层次分明。

产出 `design-preview/course-border-verification-v1.0.html` + `assets/course-border-v1.0/`。
