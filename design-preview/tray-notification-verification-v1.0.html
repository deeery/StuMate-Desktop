推翻两条旧结论。代码注释里曾写「不设 AUMID → Windows 11 直接吞掉气泡」与 「设 AUMID 必须早于任何窗口」。两组对照都复现不出来，两条都已从注释里删除。 它们极可能都是假阴性：气泡由 Explorer 托管、不是本进程窗口， 早先靠外部脚本「等 N 秒再全屏抓」，抓早了、或被 Windows 对内容完全相同的 Toast 去重，都会得到「什么都没弹」的假象。现在探针在进程内自取基线与 after 做差分， 时序不再靠运气。

三、改了什么

文件改动
platform/AppIdentity.kt 进程内往 HKCU\SOFTWARE\Classes\AppUserModelId\StuMate.Desktop.1 写 DisplayName=StuMate，覆盖便携包 / gradlew run / MSI 三种安装方式（HKCU 不需要管理员权限，优先级高于 HKLM）。
tools/postprocess_msi.py 🔴 原来把值名写成了 StuMate（应用名本身）， 而 Shell 只认值名恰好为 DisplayName 的项 —— 等于没注册。 已改，并补上 IconUri。
src/test/…/AppIdentityTest.kt 跨文件断言：值名必须是 DisplayName、AUMID 与显示名要和打包脚本逐字一致。 不一致不会报错、只会静默退化，所以交给测试守。
Main.kt AppIdentity.install() 提到 application { } 之外 —— 符合文档要求的时机，不花代价；但不作为已验证的根因。
dev/TrayProbe.kt 进程内自截图 + 差分判定，打印 气泡可见 = true/false； 新增 noDisplayName / 修正后的 awtFirst 对照组。

四、怎么复跑这三组对照

# ① 不设 AUMID ./gradlew trayProbe -PnoAumid=1 -Ptag=NOAUMID -Pshot=F:/tmp/s1 # ② 只设 AUMID、不注册显示名（先删掉 HKCU 那把键，否则会被上一轮写回去） ./gradlew trayProbe -PnoDisplayName=1 -Ptag=NODISP -Pshot=F:/tmp/s2 # ③ 正常（设 AUMID + 注册显示名） ./gradlew trayProbe -Ptag=FIXED -Pshot=F:/tmp/s3
真实 App 已验证。换入新构建的 F:\DownloadQQ\unpacked\StuMate 启动后， HKCU\SOFTWARE\Classes\AppUserModelId\StuMate.Desktop.1 下自动出现 DisplayName = StuMate（原先只有一个被误命名的值）， 该实例发出的任何气泡都会以「StuMate」为标题。桌面端单测 199/199 全绿。

五、同批次修的另一个 bug：云同步把同一门课存成多份

症状：课表里冒出一堆所有字段完全一致的重复课程。
根因 1：服务端 pull 返回的是原始变更流水而非「每条记录一条」， 同一 uid 改过几次就有几条；而落库时用的是循环外的旧快照且从不更新， 于是第二条查不到刚写的行 → 当成新记录 → 另分配 id → INSERT 出第二行。 实测某账号 72 个 uid 里 52 个有 2~4 条修订。
根因 2：两台设备各建同一门课 → uid 不同 → 服务端两条。
修法：① 落库改成「活索引 + 内容指纹表」，同一 uid 覆盖同一行； ② 同步前先收敛本地脏数据：同 uid 多行物理删多余行； 内容一致但 uid 不同的败者写墓碑推给服务端（直接删会在全量重拉时复活）， 留 uid 字典序最小的那条 —— 必须确定性，否则两台设备会「你删我、我删你」把课删没。
