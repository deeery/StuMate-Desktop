置顶提醒卡片「背景透明」修复 · 验收页 v1.0

反馈：「桌面端提醒需要优化；置顶卡片会让屏幕其他部分变黑。让其他部分保持透明。」
查下来是**两个原因叠在一起**，只去掉那层黑色遮罩治不了本 —— 详见下面「根因」。

一、根因（实测，不是推测）

#问题证据
1 卡片外面铺了一层 80% 黑遮罩 Color(0xCC000000)， 把整屏压暗 —— 用户正看课件/视频时等于被盖掉。 源码 OverlayContent 的第一层 Box 背景色
2 更根本：Window(transparent = true) 没有真的建出分层窗口， 卡片以外的区域本来就是不透明的纯黑。 GetWindowLongW(hwnd, GWL_EXSTYLE) → 0x00080008，WS_EX_LAYERED 未置位； 屏幕采样 (1400,1000) = (0,0,0)

⚠️ 顺带排除了「环境不支持」这个可能：GraphicsDevice.isWindowTranslucencySupported( PERPIXEL_TRANSLUCENT) 返回 true，headless = false —— 平台是支持的，是 Compose 这条路径没走到。
所以只删遮罩的话，用户看到的仍然是一块黑，只是没那么黑 —— 问题没解决。

二、修法：色键透明（color key）

不再依赖 AWT 的逐像素透明，改成自己给窗口加 WS_EX_LAYERED， 再用 SetLayeredWindowAttributes(..., LWA_COLORKEY) 指定一个「魔术色」： 画成这个颜色的像素被 DWM 当作全透明。

收益说明
背景真的透明卡片以外原样露出底下的画面，不再压暗、不再变黑
鼠标自动穿透 色键像素按定义就不接收点击 —— 「看得见」和「点得到」一次拿到， 不需要再轮询鼠标位置去动态切 WS_EX_TRANSPARENT
卡片照常可点卡片本身不是魔术色，命中测试不变，「知道了」按钮正常

魔术色选品红（0xFF00FF）：离 Fluent 调色板（灰 / 蓝）最远， 卡片圆角抗锯齿混出来的 1px 边最不显眼。
⚠️ 代价是卡片边缘可能有极细的品红描边，需要在真机上看一眼 —— 见下面「需要你确认的」。

三、验证证据

直接问 Windows「这个窗口的色键到底登记成什么了」，比看截图可靠 —— 因为截图能不能拍到分层窗口是另一回事（见下方说明）。 

窗口 'StuMate 提醒'  rect=(0, 0, 2800, 2000)
   exstyle=0x00080008   LAYERED=True   TRANSPARENT=False

色键登记：ok=1  key=0xFF00FF  flags=0x1（LWA_COLORKEY=0x1；期望 key 0xFF00FF）
检查项结果
WS_EX_LAYERED 已置位是
色键颜色登记为 0xFF00FF是（ok=1）
抓屏里出现品红残留 无 —— 说明 DWM 确实把魔术色吃掉了，而不是原样画出来
桌面端编译 / 单测BUILD SUCCESSFUL / 160/160
移动端编译 / 单测BUILD SUCCESSFUL / 153/153

为什么截图里的背景是白色，而不是「底下的窗口」： ImageGrab.grab() 走的是 BitBlt， 它对色键挖出来的洞取不到数据，返回白色（未初始化）。 试过 include_layered_windows=True 也一样。 换句话说：这张图能证明「黑色没了」，但证明不了「底下的画面透出来了」 —— 后者只能靠眼睛，所以需要你确认。

五、需要你确认的

  • 提醒弹出时，卡片以外是否真的看得见你正在看的内容（而不是黑 / 白）。
  • 卡片圆角边缘有没有品红描边（抗锯齿与魔术色混合的副作用）。
  • 在卡片以外的地方能不能正常点到别的窗口（鼠标穿透）。

预览入口：./gradlew uiPreview -Ppreview=overlay， 或直接跑主程序等一次真实提醒。
