课表页「悬浮无反馈 + 点击延迟极大」修复验收

StuMate 桌面版 · Compose Multiplatform 1.5.10 · 2026-09-30 · 改动文件 ui/fluent/WeekPage.kt（唯一改动文件）
修复前 鼠标划过课程块：毫无反应；单击课程块：约 300ms 后才响应
修复后 悬浮：整列 + 表头 + 课程块三处同时亮起；单击：23.4ms（与普通按钮同级）

1 · 两个问题，两个不同的根因

根因 A：单击延迟 = 双击判定超时

CourseBlock 原来用 detectTapGestures(onTap, onDoubleTap)。 为了区分「单击」和「双击」，Compose 必须在收到第一次抬起后 继续等一个双击超时窗口（ViewConfiguration.doubleTapTimeoutMillis，桌面端默认 300ms）， 期间没有第二次按下，才敢认定这是一次单击。

也就是说 —— 每一次单击都要原地僵住 300ms。 这是 API 语义决定的，不是性能问题，优化布局 / 减少重组都没用。 combinedClickable 同理。

根因 B：hover 声明了，但没人读

WeekGrid 里有三处 .hoverable(remember { MutableInteractionSource() })。 hoverable 只是把指针进出事件写进一个交互源；不读这个源就不会有任何视觉变化。 这里的源是匿名创建、创建完就丢掉，等于挂了个空转的监听器 —— 有事件，无反馈。

而 CourseBlock 连 hoverable 都没有，所以课程块悬浮是彻底没反应的。

2 · 改法

2.1 单击立即生效，双击手动计数

// 改前：单击被双击判定拖住 300ms
- .pointerInput(cls.id) {
-     detectTapGestures(onTap = { onSelect() }, onDoubleTap = { onEdit() })
- }

// 改后：单击走 clickable（抬起即触发），双击自己数时间
+ .hoverable(interaction)
+ .onPointerEvent(PointerEventType.Press) {
+     val now = System.currentTimeMillis()
+     if (now - lastPressAt in 1..DOUBLE_CLICK_MS) { lastPressAt = 0L; onEdit() }
+     else lastPressAt = now
+ }
+ .clickable(interaction, indication = null) { onSelect() }

/** 双击判定窗口 420ms（Windows 默认双击间隔 500ms，取略小值） */
private const val DOUBLE_CLICK_MS = 420L

为什么这样拆是安全的：双击时第一次单击会先把课程选中，而「选中」是幂等操作 （selectedId = cls.id），重复触发没有任何副作用；紧接着第二次按下触发编辑。 用户感知是「点一下立刻选中，再点一下弹出编辑」，中间不再有空档。

2.2 整列 hover：用指针坐标反算，而不是逐格 Enter/Exit

直觉做法是给每个表头格和每个日列各挂一个 hoverable，再共享一个 hoveredDay 状态。 但鼠标从「表头」滑到「同一天的列」时，两个相邻节点的 Exit 和 Enter 派发顺序不保证， 会出现高亮闪断。

改成在整张表上挂一个 Move 处理器，拿指针 x 直接算落在第几列：

+ .onPointerEvent(PointerEventType.Move) { event ->
+     val x = event.changes.first().position.x
+     val colPx = (gridWidth.toPx() - axisPx - sepPx * 7f) / 7f
+     val rel = x - axisPx - sepPx
+     hoveredDay = if (colPx <= 0f || rel < 0f) -1
+                  else (rel / (colPx + sepPx)).toInt().takeIf { it in 0..6 } ?: -1
+ }
+ .onPointerEvent(PointerEventType.Exit) { hoveredDay = -1 }

Exit 只在整张表上挂一次，所以不存在「相邻节点互相打断」的问题 —— 鼠标在表内移动时只走 Move 分支。 表头和日列读同一个 hoveredDay，于是「悬停表头 → 整列亮」「悬停列 → 表头也亮」天然一致。
