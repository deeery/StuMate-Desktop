## 已完成

### 工程骨架
- 新建 `C:\Users\Administrator\IdeaProjects\StuMate-Desktop`，Compose Multiplatform Desktop 单模块工程。
- **版本组合（勿改）**：Kotlin 1.9.20 + Compose Multiplatform **1.5.10** + Gradle 8.4 + JDK 17（`E:\DevTools\Java\jdk-17.0.12+7`）。
  - CMP 1.5.11/1.5.12 分别要求 Kotlin 1.9.21/1.9.22，不要升。
  - 不要手写 `kotlinCompilerExtensionVersion`，CMP 插件自动挂载。

### 环境坑（重要）
- **Gradle wrapper 不可用**：`services.gradle.org` 的重定向目标是 GitHub release assets，返回 502。
  改为项目内 `gradlew` / `gradlew.bat` 转发脚本，指向本机已缓存的
  `%USERPROFILE%\.gradle\wrapper\dists\gradle-8.4-bin\gradle-8.4\bin\gradle`。
- **`compose.material` 对 `material-icons-core` 是 runtime 作用域**，编译期不可见，
  必须显式声明 `org.jetbrains.compose.material:material-icons-core:1.5.10`。
- **CMP 1.5.10 没有 `Icons.AutoMirrored`**（1.6.0 才有），用 `Icons.Default.List` 代替。
- **`androidx.compose.ui.util.lerp` 不在默认 classpath**，需显式加
  `org.jetbrains.compose.ui:ui-util:1.5.10`。
- **`Dispatchers.Swing`** 需要 `import kotlinx.coroutines.swing.Swing`。
- **`MenuScope.Item` / `Separator` 是 `MenuScope` 的成员函数**，不是顶层扩展，不要 import。
- 截图：PowerShell 的 `Add-Type` 与 `Assembly.LoadWithPartialName` 都被沙箱拦截，
  改用 Python + Pillow（`tools/capture_window.py`）。

## 追加：自绘窗口标题栏（用户要求隐藏系统标题栏）

用户要求：把「新建提醒 / 添加便签」下沉到卡片标题行，原位置改放
「最小化 / 最大化 / 关闭」，并**整条隐藏系统标题栏**。

### 新增 `ui/fluent/WindowChrome.kt`

| 成员 | 作用 |
|---|---|
| `WindowChrome` | 持有 `ComposeWindow` + 三个回调 + `isMaximized: () -> Boolean` |
| `LocalWindowChrome` | 下发给 `PageTopBar`，避免把 window 一层层透传到 4 个页面 |
| `WindowControls(chrome)` | 自绘的三个标题栏按钮（46×32dp，贴右边缘） |
| `Modifier.windowDragArea(chrome)` | 顶栏空白处拖动窗口 + 双击切换最大化 |
| `WindowResizeHandles(chrome, state)` | 8 向缩放热区（四边 + 四角，各 5dp） |
| `workAreaOf(window)` | 屏幕减去任务栏的工作区 |

### 改动

- `Main.kt`：`Window(undecorated = true)`；构造 `WindowChrome` 并用
  `CompositionLocalProvider` 下发；内容外再叠一层 `WindowResizeHandles`。
- `AppShell.kt` 的 `PageTopBar`：去掉外层水平 padding，
  结构改为 `[标题+副标题(weight 1f, 可拖动)] [页面操作] [窗口控制]`。
- `TodayPage.kt`：页头不再放动作按钮；「新建提醒」进「今天的课」卡片标题行，
  「添加便签」进「便签 · N 条」卡片标题行（两行同为 `start 16 / end 12 / top-bottom 8`）。

### 踩到的两个 Windows 坑

1. **无边框窗口不能用 `WindowPlacement.Maximized`**：那走的是 AWT 的 `MAXIMIZED_BOTH`，
   实测 2560×1440 全屏把底部任务栏一起盖住了。改成自己算 `workAreaOf()`
   （屏幕 bounds 减 `Toolkit.getScreenInsets`）再设 `WindowState.size/position`，
   还原时用事先存下的 `restorePosition/restoreSize`。
2. **`SetForegroundWindow` 会被前台锁拒掉**（返回成功但窗口没上来），
   导致截图截到压在它上面的浏览器、点击落到别的窗口。
   解法：`SetWindowPos(HWND_TOPMOST)` → `SetWindowPos(HWND_NOTOPMOST)` → `BringWindowToTop`。
   另外「最小化→还原」之后 Windows 会吃掉紧接着的第一次点击，所以 `click-win`
   会先往侧栏空白死区点一下「热身」。
