上课提醒改版「右下角通知卡」 · 验收页 v2.0

反馈：「卡片依旧完全覆盖整个桌面，修复这个问题，或者用 WINDOWS 自带的右下角弹窗。」
→ 采用第二条：提醒改成右下角置顶小卡片，不再依赖任何逐像素透明能力。

一、为什么放弃「全屏 + 卡片以外透明」

#方案结果
1 Window(transparent = true) 没建出分层窗口 —— GWL_EXSTYLE 里 WS_EX_LAYERED 从未置位， 卡片以外是不透明的纯黑。而 isWindowTranslucencySupported(PERPIXEL_TRANSLUCENT) 返回 true，说明是 Compose 这条渲染路径没走到，不是平台不支持。
2 自己加 WS_EX_LAYERED + SetLayeredWindowAttributes(LWA_COLORKEY) API 层面看起来完全成功：GetLayeredWindowAttributes → ok=1 key=0xFF00FF flags=0x1， 截图里也没有品红残留。但实机验收仍是「完全覆盖整个桌面」。

现场证据（这次验收时抓到的）：机器上还在跑的旧版 App 正好弹了一次真实提醒 （「编译原理 14:20–15:55」），截图里整块屏幕被压成黑色 —— 那个实例带的就是色键那版代码。
更要命的是没法自证：色键挖出来的洞在 BitBlt 截图里是未初始化的白/黑， 我拿不到「透出底下画面」的证据，只能请你肉眼确认 —— 已经因此白跑过一轮。 凡是只能靠肉眼才能确认的机制，都不该用在关键路径上。

二、新方案：右下角小窗

项取值
窗口380 × 168 dp，无边框、置顶、不可缩放
位置工作区（已扣掉任务栏）右下角，留 16 dp 边距
圆角 / 描边走 DWM（Win11 原生圆角 + 跟随主题的 1px 描边），与主窗口同一套
任务栏WS_EX_TOOLWINDOW —— 不占任务栏、不进 Alt+Tab（它是一张通知，不是一个「窗口」）
抢焦点不抢。只 toFront() 抬高 z 序 —— 提醒不该把你正在输入的光标夺走
进场从右侧滑入 180 ms
关闭「知道了」按钮；点过卡片之后 Esc 也能关

左侧 3 dp 强调条与主界面卡片同一套语言；课程名一行省略号，时间与教室合并成一行。

遮挡范围是个几何事实，所以能断言，不需要人看。 新增 tools/check_overlay.py：起一次预览、量窗口矩形、查扩展样式、再采样像素。 任一条不成立就退非零 —— 可以进 CI。

第 ③ 组是这次的关键：底窗是替身「你正在看的画面」（高饱和绿 + 大字）。 采样点落在卡片外面时必须是绿色 —— 这一条直接证明「提醒没有覆盖整个桌面」， 而且是机器判的，不是我描述的。深色 / 浅色两套主题都跑过，均全绿。

五、顺带修掉一个更早就存在的 bug

查提醒位置时发现坐标系被多除了一次 density，导致 「最大化」只铺满屏幕左上四分之一（Main.kt 的 onToggleMaximize）。 

实测探针：density=2.0  screenSize=1400x636  gcBounds=1400x636  insets.bottom=48
          → 物理屏幕实为 2800x1272，工作区 2800x1176
          结论：GraphicsConfiguration.bounds 已经是 dp（AWT 用户空间 = 物理 / uiScale，
          Compose 的 density 恰好就是那个 uiScale）—— 不该再除

六、你需要做的

  • 重启一下 App：现在跑着的那个实例还是旧代码，它弹的还是全屏黑色覆盖层。 重启后提醒才会变成右下角小卡片。
  • 如果想再确认一次，跑 python tools/check_overlay.py（约 40 秒，全绿即通过）。

不需要再肉眼判断透明度了 —— 这次没有任何「只有眼睛能验」的机制。

七、仍然存在的限制（与安卓的差异）

  • 安卓是全屏覆盖 + 能压在锁屏上；Windows 这里只是右下角一块， 对独占全屏的游戏 / 播放器仍可能被压住（与安卓上 ColorOS 拦截全屏弹窗同类）。
  • 多屏时固定落在主屏（跟鼠标跑反而让人找不到，系统通知也是固定主屏）。
