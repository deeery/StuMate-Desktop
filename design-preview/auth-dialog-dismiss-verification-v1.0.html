1改了什么

原来所有对话框都走 FlDialog，而它是 Dialog(onDismissRequest = onDismiss) —— 用 DialogProperties 的默认值，即点外面关、按 Esc 也关。 登录框里躺着用户刚敲的邮箱、密码、邀请码，误触一下就全清空了。

改动一：给 FlDialog 加一个开关

// FluentControls.kt
 fun FlDialog(
     onDismiss: () -> Unit,
     title: String,
     width: Dp = 440.dp,
+    /**
+     * 是否允许「点对话框外面」或「按 Esc」把它关掉。
+     *
+     * 登录 / 注册这类对话框要传 `false`：里面是用户刚敲进去的邮箱、密码、邀请码，
+     * 误点一下空白处或误按 Esc 就全没了，只能靠「取消」显式关闭。
+     *
+     * 这两个关闭途径在 Compose 里是两个独立开关（`dismissOnClickOutside` 管点击、
+     * `dismissOnBackPress` 管 Esc —— 桌面端 Esc 就是走 back-press 这条路的），
+     * 这里合成一个语义「能不能被外部操作关掉」，避免调用点每次都要写两遍。
+     */
+    dismissible: Boolean = true,
     content: @Composable () -> Unit,
     actions: @Composable RowScope.() -> Unit
 ) {
     val c = FluentTheme.colors
-    Dialog(onDismissRequest = onDismiss) {
+    Dialog(
+        onDismissRequest = onDismiss,
+        properties = DialogProperties(
+            dismissOnBackPress = dismissible,
+            dismissOnClickOutside = dismissible
+        )
+    ) {

2为什么两个开关都要关（Esc 也算）

「点外面」和「按 Esc」在 Compose 里是两条独立通路，只关前者的话 Esc 仍会把对话框关掉。 这一点是从 Compose 1.5.10 的字节码里确认的，不是猜的： 

# 反编译 ui-desktop-1.5.10.jar 里的 androidx/compose/ui/window/Dialog_skikoKt.class
# ① 什么算「back」—— 桌面端就是 Esc 键
private static final boolean isDismissRequest-ZmokQxo(java.lang.Object);
    KeyEventType == KeyDown  &&  Key == Key.Companion.getEscape()

# ② 整段 back 处理被 dismissOnBackPress 卡着
     434: invokevirtual  DialogProperties.getDismissOnBackPress:()Z
     437: ifeq  567            # false 就跳到 567，即整段跳过

# ③ 「点外面」走另一个开关
     588: invokevirtual  DialogProperties.getDismissOnClickOutside:()Z
结论 把 dismissOnClickOutside 和 dismissOnBackPress 同时置 false， 才是「只有点取消能关」。只关一个的话，另一条路仍然会把对话框关掉、把输入清空。

5怎么验（需要您亲手点一下）

这个改动是行为变化，没有视觉差异，截图证明不了「点了没关」。 而这台机器的鼠标注入不可用（实测 SetCursorPos(500,500) 落到了 (344,506)， 比例还不一致，怀疑是您同时在动鼠标），所以没法由我代点。请您按下面三步确认：

  1. 应用左侧点「设置」→ 在「账号」分组点「登录 / 注册」。
  2. 对话框出来后，点它外面的任何地方（左侧栏、页头、对话框周围那片暗色遮罩）—— 预期：对话框纹丝不动，不会消失。
  3. 点右下角「取消」—— 预期：正常关闭。
想顺便验 Esc 按一下 Esc，预期也是不关闭（这就是上面那第二个开关的作用）。 如果您希望 Esc 仍然能关、只禁止点外面，把 dismissOnBackPress 单独改回 true 即可。
