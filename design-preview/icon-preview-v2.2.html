二、缩放系数怎么定的

Lucide 铃铛的视觉外接框（含 2 单位描边各外扩 1）是 19.478 × 22，中心 (12.001, 12)。三个候选都渲染出来比过：

scale视觉宽结论
12.116236与 v2.1 等宽，但描边版视觉分量轻，26dp 下显得比旧图标小一圈
12.6245采用：比 v2.1 略大，补回描边损失的视觉分量，又不压到九宫格
13.1255更大，26dp 收益不明显，开始显得挤

落到 512 画布后铃铛占 x 133→379、y 117→395，描边实际宽 25.2 单位（26dp 下约 1.3px）。

六、落到代码

Compose 1.5.10 的 addGroup 没有尾随 lambda —— 这是本轮唯一踩到的编译坑

直觉写法是 builder.addGroup(...) { addPath(...) }，编译报 Type mismatch: inferred type is () -> Unit but List<PathNode> was expected。 它的真实签名最后一个参数是 clipPathData: List<PathNode>， 返回一个「作用域指向该 group」的新 builder：

val bell = builder.addGroup(
    name = "lucide-bell",
    scaleX = BELL_SCALE, scaleY = BELL_SCALE,
    translationX = BELL_TX, translationY = BELL_TY
)
bell.addPath(pathData = addPathNodes(BELL_BODY), stroke = bellStroke,
             strokeLineWidth = BELL_STROKE,
             strokeLineCap = StrokeCap.Round, strokeLineJoin = StrokeJoin.Round)

group 变换语义（反编译 ui-desktop-1.5.10 的 GroupComponent.updateMatrix 确认）

Matrix.translate(tx + pivotX, ty + pivotY)
Matrix.rotateZ(rotation)
Matrix.scale(sx, sy)
Matrix.translate(-pivotX, -pivotY)   // pivot 取 0 ⇒ p → s·p + t
// draw() 里 drawContext.transform.transform(groupMatrix)
// ⇒ group 内的 strokeLineWidth 也按 s 一起缩放

所以 strokeLineWidth = 2f 写在 24 空间里是对的，会自动随 scale 变成 512 空间的 25.2。
