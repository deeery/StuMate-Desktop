课程常驻描边 —— 给每一节课一个默认边框

之前只有选中 / 悬浮时才有描边，默认态下课程块和背景完全分不开

像素实测通过 单测 145 / 145 深浅双主题 2026-10-01 v1.0

1. 问题在哪

课表格子里每个课程块的描边是这样定义的：

val borderWidth = when {
    selected -> 1.5.dp
    hovered  -> 1.dp
    else     -> 0.dp        // ← 默认态完全没有描边
}

所以这是交互态描边，不是常驻描边。 默认状态下，一节课和旁边那节课、和格子底色都是同一种颜色， 整张表看起来像「散落几块灰色方块」，而不是「一节节课」。

2. 改完之后

深色主题 —— 每一节课都有完整边框，边界清晰但不生硬
浅色主题 —— 描边内凹，符合纸质表格直觉

3. 描边色的选择：为什么不复用现成 token

先算了候选色的实际亮度差（#333333 卡片面 / #E0E0E0 卡片面）：

候选 色值 深色下 Δ 浅色下 Δ 结论
outline #3A3A3A Δ 7#E5E5E5 Δ 5 太弱肉眼找不到
outlineStrong #4A4A4A Δ 23#C8C8C8 Δ 24 太强像选中态
bg（第一版） #141414 Δ 31#F3F3F3 Δ 19 过硬像挖出来的槽
borderRest（采用） #404040
#D2D2D2		 Δ 13Δ 14 采用边界可读且柔和
第一版试了 c.bg，效果不对。 深色下 Δ 31 确实够清楚，但方向是「比卡片面暗」—— 在深色主题里看着像每个格子都被挖空了，边框硬得像刻上去的槽。 Fluent 的实际做法是让边界发光，不是挖槽。 所以改成深色下比卡片面亮（#404040）、浅色下比卡片面暗（#D2D2D2）， 两个主题都落在 13–14 级这个舒适区间。

新增 token

/** 常驻描边：课表格子里每一个课程块的默认边框 */
val borderRest: Color

// 深色
borderRest = Color(0xFF404040)   // surface3 #333333 之上，Δ +13
// 浅色
borderRest = Color(0xFFD2D2D2)   // surface3 #E0E0E0 之下，Δ +14

4. 一个容易漏的顺序问题

border() 画在组件内侧。原来的顺序是 clip → background → border， 于是 4dp 圆角处把描边切出缺口，四角连不上（表现为四个小断口）。

// ⚠️ border 必须在 clip 之前
.border(borderWidth, borderColor, RoundedCornerShape(4.dp))
.clip(RoundedCornerShape(4.dp))
.background(bg)

放到 clip 之前，描边完整绕一圈，圆角处也是连续的。

5. 像素实测

肉眼判断「这线够不够明显」不可靠 —— 深色下差十几级肉眼几乎看不见，截图缩小后又被抹平。 所以沿课程块左边界做垂直扫描，直接看颜色跳变：

扫描 x=300 这条竖线上的颜色跳变:
  y=141: #2B2B2B -> #3A3A3A   ← 格子底 → 整点分隔线
  y=142: #3A3A3A -> #141414
  y=143: #141414 -> #333333   ← 分隔线 → 课程卡片面
  y=144: #333333 -> #404040   ← 课程描边
  y=145: #404040 -> #333333   ← 描边结束，回到卡片面
  y=151: #333333 -> #FFFFFF   ← 课程标题文字
#333333 → #404040 → #333333 —— 描边精确落在设定值上， 1 像素实打实、没有抗锯齿摊薄（对比 y=142 的 #141414 是整点分隔线， 两者层次分明不混淆）。
