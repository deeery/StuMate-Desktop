1这次做了什么

桌面端此前完全没有登录能力 —— 服务端接口早已上线，客户端一行都没有。本次把整条链路补齐：

层次内容
网络层HttpJson.kt：JDK 17 自带 java.net.http + 自研 MiniJson 薄封装。超时 connect 10s / request 20s；非 2xx 解析 {error:{code,message}}；IOException 归一成 ApiException("NETWORK")。零新增依赖。
接口层AuthApi.kt：health / 邀请码校验 / 注册 / 登录 / refresh / logout / 改密 / 重置密码 / me / 改昵称 / 设备列表 / 踢设备 / OAuth start / bind / unbind / poll，共 17 个方法。
会话层AccountSession.kt：全局唯一令牌持有者。refresh 轮转（先落盘再返回）、并发刷新双重检查、401 自动重试一次、OAuth 轮询抗网络抖动。
凭证存储SecretStore.kt：JNA 调 Windows DPAPI（crypt32.CryptProtectData）加密落盘到 %APPDATA%\StuMate\credentials.bin，自定义 10 字节文件头，失败降级明文并标记。熵常量固定，发布后不可更改。
浏览器跳转Browser.kt：AWT Desktop.Action.BROWSE → rundll32 url.dll 两级降级。
界面设置页新增「账号」分组 + 5 个对话框：登录/注册（同一对话框切标签）、重置密码、设备管理、改昵称、OAuth 等待授权面板。
启动接线Main.kt 启动时 AccountSession.restore() 恢复登录态；不阻塞启动流程，界面不会被登录卡住。

2接口冒烟：对着真实服务端跑了一遍

./gradlew apiSmoke 会真的去连 https://deeer.online/api/stumate/v1。8 项全过：

结果检查项实测
√GET /health 服务端可达version = stumate/v1
√GET /auth/invite/check 不存在的码判无效valid=false
√POST /auth/login 错误凭据返回 BAD_CREDENTIALSHTTP 401
√登录接口不泄露账号存在性短密码与长密码返回码一致
√POST /oauth/github/start 返回真实授权地址host=github.com，有效期 600s
√POST /oauth/google/start 凭据未配置时明确报错PROVIDER_NOT_CONFIGURED (503)
√GET /oauth/github/poll 无效 state 报错NOT_FOUND（404，非 200）
√GET /me 未认证被拒绝401 UNAUTHORIZED
冒烟测试查出并修掉的两个真问题 ① oauthPoll 对无效 state 抛异常而不是返回值 —— 调用方得在 catch 分支和返回值分支分别处理「失败」，迟早漏一边。已改成 OAuthPollResult.Failed，网络类异常仍继续上抛（轮询循环会忽略它继续等，不浪费 10 分钟授权窗口）。
② 登录接口不校验密码长度 —— 这不是 bug：文档里「最少 8 位」只对注册与改密生效。登录刻意不校验，否则可用返回码差异枚举账号是否存在。测试预期已按此修正。

4几条值得单独说的设计约束

约束为什么
refresh 先落盘再返回 服务端对 refresh 做了轮转 + 重放检测。如果先把新令牌返回给调用方、落盘晚一步，进程此刻崩溃 = 下次拿旧令牌重放 = 整台设备令牌链作废。顺序反了就是事故。
并发刷新加互斥锁 + 双重检查 两个协程同时刷新会各自拿到新令牌，后落盘的把先落盘的覆盖掉 —— 又是一次重放。锁内二次判断 needsRefresh，保证只发一次。
只有 401 才降级为未登录 网络故障（ApiException.isNetwork）保持登录态，只是「离线」。否则地铁里打开应用就会被登出，用户会以为数据丢了。
令牌用 DPAPI 加密落盘 Windows 的 DPAPI 把密钥绑到当前用户账户，别的用户/别的机器拿到 credentials.bin 也解不开。JNA 直接调 crypt32，不引入原生依赖。
登录接口不校验密码长度 若登录对短密码返回 BAD_REQUEST、对长密码返回 BAD_CREDENTIALS，就能靠返回码差异枚举账号是否存在。冒烟测试专门锁住了这条。

5没做到的 / 需要你确认的

① 没能截到「已登录」状态

本机没有可用测试账号，注册又需要管理员生成邀请码。所以 「已登录」界面（昵称头像、第三方账号绑定、设备列表、退出登录）目前只有代码，没有截图。 代码路径已经写好（预览入口支持 -Pemail=… -Ppassword=… 真实登录一次），只差一份凭据。

② 已知未完成（不在本次范围）

  • 服务端 同步接口未实现：/sync/push、/sync/pull、/sync/status 都还没有（records / sync_log 表已建）。所以界面文案写的是「同步功能仍在开发中」。
  • Google OAuth 凭据未配：代码已就位，服务端返回 PROVIDER_NOT_CONFIGURED，按钮点了会给出明确提示而不是静默失败。
  • 改动尚未提交（桌面端 P2 + P3 均在工作区）。
需要你拍板：设置页的默认分组 原来默认落在「提醒」。我把「账号」加在了列表第一位，同时把默认选中也改成了「账号」—— 理由是列表顺序与默认选中不一致时，导航第一项未选中会看起来像 bug；且设计文档里「首次启动不弹登录，设置页『账号』分组显示『未登录 · 点此登录』」也需要一个自然落点。

代价：每次打开设置都会先看到账号页，而不是日常更常用的提醒设置。
回退成本：SettingsPage.kt 里改一个字面量（SettingsSection.ACCOUNT → REMINDER），账号分组保留在列表首位。你说改我就改。

③ 顺手清掉的既有问题

  • SettingsPage.kt 里一个未使用的 val c（编译告警）。目前还剩 2 个既有告警（SettingsPage.kt 的未用变量），非本次引入。
